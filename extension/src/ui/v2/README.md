# B2 v2 UI handoff

Import views from `src/ui/v2` and retain the existing `src/ui/theme.css` shadow stylesheet (it includes v2 styles). Mount inside `.breakpoint-shell` with `data-theme="light"` or `"dark"`.

## A3 runtime integration

- **Agreed A3 export:** `TimelineMarkers` from `src/ui/v2`, with `{markers: Array<{id: string; timeS: number; position: number; title: string; kind: 'coding'|'concept'; concepts: string[]; status: 'upcoming'|'attempted'|'passed'}>; onSelect(id: string): void}` exactly as requested in #6716896022. Position is percent (clamped 0–100); non-finite positions/times are omitted. Runtime must provide only current ready validated items. Attempted stays unfinished; passed is Review. `TimelineChallenges` below is a plan-shaped adapter/showcase using the same presentation.

- `TimelineChallenges` is exported from `src/ui/TimelineChallenges.tsx`. Props: `{pauses: readonly PlanPause[], durationS: number, passedIds?: ReadonlySet<string>, onOpen(pauseId: string): void}`. Pass validated pauses eligible under current frequency/settings. `passedIds` contains **pause ids**. It renders only ready pauses with the matching exercise/question and a finite timestamp inside the duration. Markers cluster automatically at the measured container width; a cluster opens a nearby list, and the Challenges disclosure lists every ready item. Tooltips name title/concepts/time/status; passed items use a check and Review label. Mount this in your timeline host with the existing shadow theme. A3 owns placement, scheduling, seek/reopen and event guards; opening/reviewing must not create duplicate completion or XP.
- `PracticePanel` and `ConceptQuestionPanel` now put **Practice later** under **More**. They still call the existing `onSkip` callback, including during requests/errors. No completion state or XP is awarded in presentation code. Runtime must keep skipped pauses unfinished and emit only its existing skip event. More supports Tab/Enter and Escape; Close remains directly available.
- The coding editor card cannot shrink below 212px; body children retain their height and the body scrolls. New hints open automatically and collapse older ones; earlier hints and sources remain available through named disclosure buttons.

- `ConceptQuestionPanel` preserves the frozen props. Optional `error?: {code, message, retryable} | null` and `canResume?: boolean` display failed requests and rejected playback without losing the answer. `onAnswer` sends the selected **choice id**, or trimmed text for short-answer/output questions. The parent owns requests, stale-result rejection and `checking`. Skip/Close stay enabled while checking. Correct feedback exposes explicit Resume; it never plays media itself. Change question id/revision to reset the form. Heading focus moves in and returns on unmount.
- `FeedbackCard({ feedback, code })` shows the contract result. Pass the exact **submitted code**, not the current draft. Diagnosis lines highlight a read-only CodeMirror snapshot; line notes also appear as accessible text. Out-of-range, fractional and duplicate line numbers cannot create invalid ranges. Optimization appears only when `success.optimization.show` is true. The server owns that tier decision.
- Existing `PracticePanel` accepts optional `conceptLevels: {concept, level}[]`, `levelUp: {concept, level} | null`, and `feedback: {result: FeedbackResult, submittedCode: string} | null`. `manualResume?: boolean` keeps solved feedback visible with explicit Resume video and no countdown or rejected-play warning. This adds chips, a level-up announcement and feedback without changing v1 callers. Pass optional `language: Language` from the plan exercise and `accountId: string` from the active attempt. The editor uses the matching filename and accessible language label; Python, JavaScript/TypeScript, Java, C/C++, SQL, Rust, Go and C# use their matching syntax parsers; pseudocode and unknown languages remain plain text. Non-Python examples/results use JSON values. Drafts remount on account changes and use `practiceDraftKey(videoId, exerciseId, revision, accountId)` from `src/drafts.ts`; v2 keys are `account/${encodeURIComponent(accountId)}/${videoId}/${exerciseId}/${revision}`. Omitted accountId preserves legacy v1 keys. Do not copy legacy drafts into other accounts. `LevelChip` and `LevelUp` are independently reusable.
- `TopicNotAvailable({ reason, onDismiss })` and `RefresherPrompt({ due, onStart, onDismiss })` are presentation only. `due` is `PublicProfile.refresherDue`; Start returns the first due concept id. The parent requests `/v2/refresher/{accountId}` and mounts the returned question, handles 204, and controls dismissal lifetime.
- `LearnerSettings({value, videoId?, onChange})` is controlled. Value is `{frequency: 'few'|'normal'|'many', autoPause: boolean, disabledVideos: string[]}`. Passing a video id exposes Never pause on this video. Runtime owns immediate enforcement, persistence, and storage-change observation.

The popup saves settings at `chrome.storage.local['breakpoint:learner-settings']` (`SETTINGS_KEY`), selected account id at `['breakpoint:active-account']` (`ACCOUNT_KEY`), aligned with lead clarification #6716393647. Default is normal, auto-pause on, empty exclusions. Popup writes serialize to preserve the latest choice. The first available backend account is used if no saved valid selection exists. The popup uses A3's `loadLearnerSettings`, `saveLearnerSettings`, `loadActiveAccount` and `setActiveAccount` helpers from `src/plan/preferences.ts`. Malformed settings use A3's fail-closed defaults. The standalone showcase injects preview preferences because it has no extension context.

## B1 profile integration

`ProfilePage` loads `GET /v2/accounts`, accepting an array of `{accountId, displayName}` or `{accounts: [...]}`, then `GET /v2/profile/{accountId}` with the frozen public-profile shape. Both responses are validated. Account changes abort old requests; 6 s deadlines, offline/501/malformed data, empty accounts and storage errors have recovery states. No fixture data is bundled as a live profile. B1 confirmed `{accounts: [{accountId, displayName, public}]}` in #6716580287; the parser accepts and strips the extra public field. `ProfileView({profile})` is separately usable in fixture tests. Recommendations show up to three supplied skills and only link to HTTPS YouTube URLs.

## Proof and showcase

`npm run typecheck`, `npm test`, `npm run build`, then `npm run test:e2e -- --grep v2`.

Open `/tests/showcase/v2.html?state=question&theme=dark` on the existing Vite preview server. States: question, short, predict, question-checking, question-passed, question-error, question-resume-error, failed, passed, beginner-passed, coding-level, coding-passed, coding-language (optional `language` query), coding-accounts, level-up, profile, profile-live, refresher, settings, unavailable. `profile-live` uses the real API; other states are explicitly fixture-only. All visual states are captured at both configured viewport sizes and themes by `v2.preview.spec.ts`; `v2-popup.spec.ts` exercises the built MV3 popup, loopback API, and Chrome storage. Outputs are in ignored `extension/test-results/`; captured evidence is in `extension/assets/ui-checks/v2/`.

This lane does not claim live any-video planning, real provider grading or mounted v2 content-script playback. A3 owns those integration gates.
